## Contract and changes

- Workflow metadata added to `ResolutionRun`: version 1 by default, legacy read
  state, workflow/decision/cluster/golden revisions 0. No synthetic decisions or
  reruns backfilled. Unknown versions/states deny actions and return a blocker.
- Eight registered additive models in `mdm/workflow_models.py`: operations,
  immutable-snapshot metadata, cluster generation/membership, conflicts, golden
  drafts/selections, profiles. Existing record/proposal/entity identities retained.
  Runtime snapshot immutability/publication and golden services belong to S03–S05.
- `WorkflowRead`/`OperationRead` include revisions, counters with units,
  operations/progress/error/timestamps, blockers and allowed actions.
- Mounted authenticated owner-scoped GET `/api/v1/mdm/runs/{run_id}/workflow`
  and `/operations/{operation_id}`. GET creates no job/output. No workflow mutation
  endpoints enabled before stage execution is implemented in S02–S05.
- `begin_operation` holds the existing run lock and atomically persists operation,
  audit, state/revision and one task slot; payload-mismatched request ID returns
  409; matching replay returns prior operation before stale checks. Terminal task
  reuse preserves history and resets only slot ownership/counters.
- `ResolutionTask` unique run_id retained. Attempt/Claim include operation ID;
  queue claim/progress/failure/retry/success preserve operation identity; old
  attempt fences remain enforced. No multiple active slots per run.
- Legacy `/start` rejects v2 with 409; currently no public API creates v2 runs.
  Stage dispatcher/upload opt-in integration is S02. Existing v1 paths unchanged.
- Migration `0029_session_workflow` after actual merge head `0028_merge_llm_policy`.
  Defaults preserve legacy; downgrade retains additive metadata/history; reupgrade
  idempotent. Runtime readiness/worker HEAD updated.
- Older migration fixture now seeds the actual reflected 0018 schema instead of
  trying to insert newer ORM workflow columns. Preservation assertions retained.
