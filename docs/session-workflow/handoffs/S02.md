# S02 — PREPARE/DECIDE separation and durable pair publication

Campaign `20261011-workflow-01`. S02 PASS for implemented stage separation;
live R2/LLM, review/finalize/cluster/golden and deployment remain uncertified.

## Changes and contract

- Opt-in `SESSION_WORKFLOW_ENABLED` creates v2 runs and atomically queues PREPARE
  at the import transaction. Existing v1 defaults and imported normalization stay intact.
- Operation-scoped worker dispatcher executes PREPARE or DECIDE. Legacy `/start`,
  direct unclaimed `run_pipeline` and legacy pair mutation cannot run v2 clustering.
- PREPARE stores bounded schema/raw/normalized/quality/source profile in PostgreSQL.
  Current native importer rejects invalid input atomically; profile explicitly describes
  that contract rather than claiming row-level quarantine support not yet implemented.
- Mounted GET data-profile and CSRF/owner/capability-protected POST start-decide.
  Same request/payload replays its operation; stale/state/payload conflicts fail.
- Shared compute and StageRunner have explicit DECIDE phase. It retains all candidates,
  including insufficient evidence; matcher scores and thresholds are unchanged.
  No proposal/golden construction occurs; annotations bind before clustering in this phase.
- Checkpoint phase `decisions` is distinct from legacy `cluster` with phase-pinned config,
  upstream dependency/checksum/coverage validation and resumable durable artifacts.
- Pair output seals to Parquet; upload/read-back receipt validated before publication.
  Downloaded bytes rechecked, run/input/operation/attempt identities fenced. Pair serving,
  state and operation completion commit atomically. No partial generation serves pairs.
- StageRunner closes its snapshot on success/failure. DuckDB Arrow tables registered
  explicitly and existing unused context/whitespace lint findings corrected in this module.
  This fixes inherited WF-D001 (Windows SQLite index handle) without dataset-specific code.
